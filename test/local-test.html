本页所有素材（m3u8 播放列表 / TS 分片 / MP4 文件）都由你本机的 serve_local.mjs 提供， 不依赖外网，因此验证结果稳定可复现。

验证步骤

  1. 确认扩展已安装并在工具栏中（紫色下载图标，可在扩展菜单里「固定」）。
  2. 让下面「测试 1」的按钮跑一次（点一下即可制造网络请求）。
  3. 点击工具栏的扩展图标 → 列表中应出现 stream.m3u8（HLS）、seg0/1/2.ts（分片）、flower.mp4（视频文件）。
  4. 对 stream.m3u8 点「选择清晰度」→ 面板显示「直接下载 · 共 3 个分片」→ 点击。
  5. 上方「下载任务」区观察进度，完成后去浏览器下载目录查看文件。
  6. 最后点「测试 4」的按钮，验证 DASH 音视频分离 → 自动合并（即 B站 那个问题的修复）。

测试 4：DASH 音视频分离 → 自动合并（重点！）

这两条 .m4s 是从 B站 真实抓取的样本：视频轨只有画面、音频轨只有声音（B站 等 DASH 站点就是这样拆开传输的）。 请求完成后打开扩展：

  • movie-1-30080.m4s 应显示为 M4S·视频，副标题含 avc1 与分辨率，按钮为 「下载（含声音）」，下方提示"两条独立流，会自动合并"；
  • movie-1-30280.m4s 应显示为 M4S·音频（mp4a、声道/采样率），并提示"已被自动合并，一般无需单独下载"。

验证的关键一步：点视频轨那条的「下载（含声音）」，完成后到下载目录查看—— 只应产生 1 个 .mp4 文件，并且既有画面也有声音（样本只含开头约 5 秒，时长显示为 45 秒属正常，因为文件头声明了完整时长）。 如果出现「一个有画面没声音 + 一个有声音没画面」两个文件，说明合并链路有问题。

测试 5：DASH 分片形态（清单里列着 init 段 + N 个分片）

真实 DASH 站点不是「一条轨一个文件」，而是 init 段 + N 个分片，清单里列着要下哪些地址。 这一份清单是把上面同样的 B站 轨道按 moof 边界切出来的（拼接回来与原文件逐字节一致）： 画面 7 个分片、声音 8 个分片。

  • stream.mpd 应显示为 DASH，下方提示"清单里有 1 条画面轨 + 1 条音频轨"，按钮为 「选择清晰度」；
  • 点「选择清晰度」→ 面板列出画面档位（分辨率 / 编码 / 码率 / 分片数）与「声音是独立音频轨，下载时会自动合并」的提示；
  • 点该档位开始下载 → 任务说明应写「已合并视频轨 + 音频轨」，并注明分片数。

验证的关键一步：完成后到下载目录查看——只应产生 1 个 .mp4， 且既有画面也有声音。这条路径专门验证「清单 → 分片下载 → 拼接 → 合并」不会把分片漏下或错序。
